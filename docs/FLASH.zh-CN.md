## 运行位置与只读检查

沿用原项目的 Python、驱动和数据线配置。关闭其他占用相机的程序。

```powershell
Set-Location -LiteralPath '<项目目录>'
$env:PYTHONPATH='src'
python -m a9tool.flash status
```

不写 `status` 时也默认为只读检查。它会查询身份、切换服务模式、读取并
保存完整原始 Backup 和目标属性，最后执行服务会话关闭流程，不写 Backup
属性或请求保存。`--help` 只显示帮助，不连接设备。

程序仅接受 ILCE-9 / 6.00 和有效序列号指纹。属性必须满足：

- 全 Backup 校验和有效，BK4 版本和数据长度可验证。
- `00020008` 长度为 1024、attr 为 0；现场读值与完整快照一致。
- `BIN!`、启用标志 1、版本标记 20160707、104 条唯一记录、`FIN!`。
- 索引范围和格式与本次研究相符，索引 `0x45` 唯一、值为 0 或 1。

检查不符即停止。不会修改保护状态以促成写入。

## 应用候选（会写入相机）

以下是用户自行运行的写入命令；本次交付没有代为执行：

```powershell
python -m a9tool.flash apply
```

该命令读取本机完整属性，动态查找表内索引 `0x45`，把其值从 1
（`STROBE_FIXED_OFF`）改为 0（`NOT_RESTRICTED`），保留所有其他记录、
表头、结束标记和填充字节。它不会把工厂模板作为整表写入。

`0x45` 是记录的索引编号，不是字节偏移，也不是独立 PID。服务写入粒度为
整个 1024 字节属性，当前已知 1→0 在数值区只改变一个实际字节。

每次操作将备份和日志放在：

```text
<项目目录>\sessions\flash\<会话目录>\Backup-original.bin
<项目目录>\sessions\flash\<会话目录>\journal.json
```

程序会在第一次写入前打印准确的 `Journal:` 路径。事务顺序为：

1. 检查身份、完整快照、属性元数据及现场一致性。
2. 将原始快照、原值、目标值及身份信息落盘，校验备份 SHA256。
3. 再读现场值，确认备份之后没有发生变化。
4. 经独立白名单发送一次精确写入，立即读取整个属性比较。
5. 回读一致后请求一次 `SAVE(0)`，再次读取整个属性比较。

已是目标值时不写入、不请求保存。任何异常都停止，不自动重试、自动回滚
或绕过保护。写入返回异常时，无法仅凭异常判断设备是否已经接收了数据；
日志会保留为 `FAILED_REVIEW_REQUIRED`。

`SAVED_AND_READBACK_VERIFIED` 只表示保存调用返回且完整属性回读一致。
服务会话结束后，需正常关机再开机核查配置采用情况。重启后 `status` 读到
0 只能进一步证明保存值仍在，不能证明运行参数已经重新计算或实际引闪。

## 从这次操作的备份恢复（会写入相机）

使用对应 `flash_apply` 操作打印的实际日志路径，替换下面的会话目录：

```powershell
python -m a9tool.flash restore --journal '<项目目录>\sessions\flash\<会话目录>\journal.json'
```

恢复会重新检查原始快照 SHA256、配置格式、日志原值和目标值，并要求
同一台 ILCE-9 / 6.00。当前整个属性必须与记录原值或目标值完全一致；
任何其他变化都会形成恢复冲突，程序停止而不覆盖。

恢复也先备份当前状态，再执行单次写入、回读、保存和回读。
它需要相机仍能正常进入服务模式，不能用于恢复已经无法建立服务连接的机身。
保留完整会话目录；PP/SLog 图形界面的“恢复全部原厂”不处理这个独立目录。

`python -m a9tool.flash` 命令行入口。目前只交付 Python 源码，没有重建旧 exe。
