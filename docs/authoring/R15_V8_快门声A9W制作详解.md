# R15／V8：快门声 SDS 编码与 A9W 制作详解

本文依据 V8 完整包中的四槽声音生成器、Sony SDS 编码器、相机端 A9W 解包器和常驻声音调度代码整理。R15 提供 LUT 等外观功能；声音包由 V8 的声音页导入和使用。A9P 与 A9W 是两种独立素材，更新滤镜不需要重新制作声音。

## 1. 文件链路和代码

```text
自有／授权 WAV、MP3、WMA 等
→ 解码为 24 kHz、单声道、有符号 16-bit PCM
→ 选择前导、归一化和尾部处理策略
→ Sony 32-byte SDS ADPCM
→ 固定 WPS1／2／3／4 槽
→ A9W V2 封包和逐槽／全包 SHA256
→ SD 卡 PRIVATE/A9FL/WPS.A9W
→ V8 声音页 OFF → Import WPS → 保存 → 冷启动
```

| 文件 | 用途 |
|---|---|
| [`encode_sony_sds_adpcm.py`](../../tools/media/a9w/encode_sony_sds_adpcm.py) | 冻结上游输入解码、归一化、SDS 搜索编码和结构检查 |
| [`make_burst_wps.py`](../../tools/media/a9w/make_burst_wps.py) | 保留 WPS1 字节，生成 LOOPL／LOOPH 的固定槽资源 |
| [`make_four_slot_wps.py`](../../tools/media/a9w/make_four_slot_wps.py) | 保留前三槽，增加 LOOPSH 第四槽并输出写卡目录 |
| [`pack_wps.py`](../../tools/media/a9w/pack_wps.py) | 已编码定长资源到 A9W V1／V2 |
| [`inspect_a9w.py`](../../tools/media/a9w/inspect_a9w.py) | 通过同一规范重新封包并逐字节比较，检查包内容 |
| [`a9_wps_pack.c/.h`](../../tools/media/a9w/reference/a9_wps_pack.c) | V8 实际使用的 C 解包与 SHA 校验规则 |
| [`a9_wps_store.c/.h`](../../tools/media/a9w/reference/a9_wps_store.c) | 双槽保存、generation 与有效记录选择 |
| [`a9_sound_resident.c/.h`](../../tools/media/a9w/reference/a9_sound_resident.c) | SINGLE／LOOPL／LOOPH／LOOPSH 请求调度 |
| [`a9_sound_auto.c/.h`](../../tools/media/a9w/reference/a9_sound_auto.c) | AUTO 的释放模式映射与状态保护 |

主机工具只使用 Python 标准库。匹配规格的 PCM WAV 可以直接读取；其他输入通常需要已有 `ffmpeg`，macOS 也保留了原工具的 `afconvert` 分支。不会自动下载软件或访问相机。

## 2. 声音槽位的固定容量

V8 的四槽配置如下。APP ID 是相机原声音资源的标识，不是音频文件里的采样率或设备编号。

| 槽／菜单 | APP ID | SDS 字节 | 帧数 | 可解码样本数 | 物理资源时长，24 kHz |
|---|---:|---:|---:|---:|---:|
| WPS1／SINGLE | `0x33` | 24,768 | 774 | 23,994 | 0.999750 s |
| WPS2／LOOPL | `0x34` | 29,760 | 930 | 28,830 | 1.201250 s |
| WPS3／LOOPH | `0x35` | 18,560 | 580 | 17,980 | 0.749167 s |
| WPS4／LOOPSH | `0x32` | 9,920 | 310 | 9,610 | 0.400417 s |

这些是**确切长度**。封包器不接受“只要比容量小”的短资源；不足部分由编码阶段补齐。超长音频应先编辑，不能随意扩大槽位或只改包头数字。

上游编码器的选项名来自 A6400 项目，保留原名以维持源码原样：

| 上游 `--slot` | 帧数 | 本项目可对应的资源 |
|---|---:|---|
| `connect` | 774 | A9 WPS1／SINGLE |
| `shutter` | 930 | A9 WPS2／LOOPL |
| `push` | 580 | A9 WPS3／LOOPH |
| `sd` | 930 | 上游 SD override，非本项目 A9W 的第四槽 |

因此制作 A9 的 WPS1 时应选择 **`--slot connect`**，不能因为“快门声”这个中文名称就选上游 `shutter`。

WPS4 借用原生 Wi-Fi 关闭提示的 APP `0x32`。RAM 绑定期间，原生 Wi-Fi 关闭提示也可能播放该自定义声音；播放 WPS4 本身不执行关闭 Wi-Fi 的操作。

## 3. 输入音频的准备

先在音频编辑器中截取真正需要的部分，尽量使用可控的短瞬态、无削波素材。长句、人声、音乐或混响可能不适合前 0.1～0.2 秒反复拼接的连拍配方；文件能通过校验并不代表循环听感自然。

统一输入为：

```text
采样率       24000 Hz
声道         1
样本格式     signed 16-bit little-endian
PCM WAV头    只属于输入／试听 WAV，不进入 SDS 槽位
```

如果需要预先转换：

```sh
ffmpeg -i my-shutter.wav -ac 1 -ar 24000 -c:a pcm_s16le prepared.wav
```

这是重采样／混音步骤；不同解码器、版本和输入有损编码可能影响最终样本。要逐字节复现，应冻结转换后的 PCM16 WAV 及 SHA256，而不只保留 MP3 文件名。

### 3.1 上游编码器的默认预处理

默认流程是：

1. 如开启前导裁剪，寻找首个绝对幅度大于 150 的样本，向前保留 5 ms。
2. 计算峰值并乘以 `29000/peak`，四舍五入、夹到 ±32767；所以这是峰值归一化，不保留原素材的绝对幅度。
3. 从尾部回找最后一个归一化后绝对幅度大于 80 的样本，再保留最多 25 ms 尾音。
4. 有效声音超过槽容量则拒绝；只有显式 `--truncate` 才裁到上限。
5. 默认最后 10 ms 线性淡出，再补零到固定样本数。

`--no-trim-lead` 只关闭**前导**裁剪，不关闭峰值归一化或尾部静音裁剪；`--tail-fade-ms 0` 只关闭淡出。需要保留绝对波形和时间布局时，使用 `make_burst_wps.py` 的 `encode_exact()` 接口，而不是假定这些参数等价于“所有预处理关闭”。

纯静音可直接用全零 SDS 帧生成。上游命令的 SNR 汇报按非零信号设计，不应把纯静音的 SNR 数值作为必须达到的制作指标。

## 4. Sony SDS 的编码和解码

本项目使用每帧 **32 字节、31 个样本**的 SDS 编码。其文件常用 `.pcm` 后缀，但内容已经压缩，不能交给原始 PCM16 播放器按两个字节一采样读取。

帧布局：

```text
byte 0：高四位 mode（0 或 1），低四位 shift（0～8）
byte 1～31：31 个 signed int8 残差码
```

解码器的 `previous` 状态在整条资源内跨帧保留。对每个残差码 `q`：

```text
mode 0：predictor = 0
mode 1：predictor = trunc(previous × 15 / 16)   （向零截断）
sample = clamp(predictor + (q << shift), −32768, 32767)
previous = sample
```

不能在每个 32 字节帧开头把 previous 清零，否则 mode1 的结果不再相同。

编码器对每帧枚举两种 mode、九种 shift，共 18 个候选。逐样本计算：

```text
q = clamp(round((target−predictor)/(1<<shift)), −128, 127)
reconstructed = clamp(predictor+(q<<shift), −32768, 32767)
error += (target−reconstructed)²
```

选择本帧平方误差最小的候选，并把**重建样本**作为后续预测状态。平局保留先枚举的候选。纯零帧且 previous 为零时直接输出 32 个零字节。Python 的 `round()` 与预测器向零截断应沿用原实现；更换舍入规则会改变字节。

`encode_exact(samples,total_frames)` 不裁前导、不归一化、不淡出，只校验 signed16 输入并补零后执行同一帧搜索。每次重新编码资源从 previous=0 开始。

成品试听必须用**最终 SDS 反解**得到的 WAV；原始 WAV 只能说明输入，不能展示量化误差、实际补齐和拼接接缝。

## 5. 制作 SINGLE 与三档连拍资源

### 5.1 先生成 WPS1

在仓库根目录执行：

```sh
python -B tools/media/a9w/encode_sony_sds_adpcm.py prepared.wav --slot connect -o media-output/single/WPS1.pcm
```

默认执行上述裁剪、归一化和淡出。输出必须为 24,768 字节。超长时优先编辑输入；若明确接受裁断，可加 `--truncate`。

### 5.2 用既有配方生成 LOOPL／LOOPH

```sh
python -B tools/media/a9w/make_burst_wps.py --wps1 media-output/single/WPS1.pcm --out media-output/three-slot
```

该步骤保持 WPS1 编码字节不变，反解 WPS1 后：

| 输出 | 有效样本制作 | 有效时长 | 补齐目标样本 |
|---|---|---:|---:|
| WPS2 | 前 4,800 样本 × 6 次 | 1.2 s | 30 |
| WPS3 | 前 2,400 样本 × 7 次 | 0.7 s | 1,180 |

WPS2／WPS3 各自按固定帧数重新编码。拼接的是反解后的 PCM 前缀，不是直接剪切 SDS 字节；直接重复含预测状态的帧不能一般性地保证同样波形。

输出含三份 `.pcm`、最终反解的 `WPS*_preview.wav`、`conversion.json`、`SHA256SUMS` 及三槽 A9W V1 写卡包。输出目录须为新目录。

### 5.3 增加 WPS4，得到 V8 四槽包

```sh
python -B tools/media/a9w/make_four_slot_wps.py --source media-output/three-slot --out media-output/four-slot
```

前三槽逐字节复制。WPS4 从 WPS1 反解样本取前 **1600** 个，即 1/15 秒，重复六次得到 9600 个有效样本，再补 10 个样本编码为 310 帧／9920 字节。

最终导入文件为：

```text
media-output/four-slot/CARD/PRIVATE/A9FL/WPS.A9W
```

该文件应为 **83,520 字节**。随目录保留四份编码资源、四个反解试听 WAV 和转换记录。

### 5.4 物理资源长度与重播间隔不同

V8 的重播间隔分别为 LOOPL 1,200,000 μs、LOOPH 700,000 μs、LOOPSH 400,000 μs。固定资源的物理时长包含补齐部分，因此并不完全等于这些间隔。

这是在 UI／输入回调中提交整段原生声音资源的调度，不是每拍一张都得到一次硬件曝光完成确认，也不是精确到采样点的无缝音频流。回调节奏、原生请求延迟及 padding 都可能影响接缝。修改包大小不会自动修改调度器间隔；制作新节奏时须同时考虑既有程序的固定调度行为。

AUTO 从释放模式快照决定 SINGLE 或三档循环。现实现对连拍 raw 模式 1 的速度 0、1、2／3 分别映射 LOOPL、LOOPH、LOOPSH；快照无效或模式未知会进入停止／保护逻辑。AUTO 下的间歇行为不能仅凭素材更换就认定已经解决。

## 6. A9W V1／V2 的精确封包格式

所有整数都是小端 u32；魔数在 V2 中仍保持 `A9WPS1\0\0`，不能按版本号自行改魔数。

| 偏移 | 内容 |
|---:|---|
| 0，8 字节 | `A9WPS1\0\0` |
| 8 | version：V1=1，V2=2 |
| 12 | 总长：V1=73600，V2=83520 |
| 16 | 头长 512 |
| 20 | mask：bit0～2／bit0～3 表示选中的自定义槽 |
| 24 | 机型／固件标识 `0x00060009` |
| 28 | 槽数：3／4 |
| 32 起 | 每槽 48 字节描述符 |

每个描述符字段为 APP ID、固定资源字节数、固定 payload 偏移、保留零，各 4 字节；随后是 32 字节槽资源 SHA256。

| 槽 | 描述符偏移 | payload 偏移 | payload 长度 |
|---|---:|---:|---:|
| WPS1 | 32 | 512 | 24768 |
| WPS2 | 80 | 25280 | 29760 |
| WPS3 | 128 | 55040 | 18560 |
| WPS4，仅 V2 | 176 | 73600 | 9920 |

选中槽的 SHA256 覆盖完整定长 SDS，包括 padding。未选中槽的 SHA 字段和 payload 区必须全零；未选不表示“保留上次自定义音”，启动绑定按该包的选择回到原资源。

全包摘要位置：V1 为 `176..207`，V2 为 `224..255`。V1 的 `208..511`、V2 的 `256..511` 为保留零。计算顺序是：

```text
payload_hash = SHA256(raw[512:total])
header_copy = raw[0:512]，将本版本的 32 字节摘要字段置零
package_hash = SHA256(header_copy || payload_hash)
```

这覆盖头部、槽描述符和所有 payload，又避免相机端为了计算摘要再分配一份大包。它是完整性校验，不是带密钥认证或数字签名。

尤其注意：**V2 的第 4 描述符占用 176～223，摘要必须移到 224**；直接在旧三槽包尾部追加音频会覆盖格式语义。

## 7. 独立封包、检查和原厂恢复包

已有四份合法定长 SDS 时，可直接封包：

```sh
python -B tools/media/a9w/pack_wps.py --wps1 WPS1.pcm --wps2 WPS2.pcm --wps3 WPS3.pcm --wps4 WPS4.pcm --out media-output/custom/WPS.A9W
python -B tools/media/a9w/inspect_a9w.py media-output/custom/WPS.A9W
```

如果没有指定 `--wps4`，原 CLI 会生成三槽 V1。需要 V2 时必须提供第 4 槽，或调用 `build_package()` 传四个元素。只选部分槽时，其他槽使用原厂资源；不要误把缺失选项理解为合并旧包。

原 `--restore-stock` 命令生成 V1、mask=0 的包：

```sh
python -B tools/media/a9w/pack_wps.py --restore-stock --out media-output/restore/WPS.A9W
```

若要明确生成四槽 V2、mask=0 的恢复包，可在已存在的工作目录执行：

```sh
python -c "import sys;sys.path.insert(0,'tools/media/a9w');from pack_wps import build_package;open('restore-v2.A9W','xb').write(build_package([None,None,None,None]))"
python -B tools/media/a9w/inspect_a9w.py restore-v2.A9W
```

恢复包仍是通过 V8 导入、保存并冷启动后生效，不是恢复固件分区或卸载 V8。先保留原自定义 A9W，以便再次导入。

检查器会复建规范包并与输入逐字节比较，因此会拒绝错误头、越界 mask、非零保留区、错误描述符、摘要损坏、未选槽非零数据、资源长度错误及非法 SDS 帧头。

可选地，用通用 C 编译器运行 V8 的实际格式解包器：

```sh
mkdir -p media-output
cc -std=c11 -O2 -Itools/media/a9w/reference tools/media/a9w/reference/validate_a9w.c tools/media/a9w/reference/a9_wps_pack.c tools/media/a9w/reference/a9_sd_sha256.c -o media-output/a9w-validate
./media-output/a9w-validate media-output/four-slot/CARD/PRIVATE/A9FL/WPS.A9W
```

这是 Linux／macOS shell 示例；Windows 可在已有的 C 工具链或 WSL 中编译这个电脑端解析器。与 A9Tool 的原生 Windows UI／通信路线无关，不运行 ARM 代码或相机命令。

## 8. 相机导入、保存与启动绑定

1. 将成品 `CARD/PRIVATE` 复制到卡槽 1 根目录，确认只有目标 `PRIVATE/A9FL/WPS.A9W`。
2. 在 V8 声音页先设为 **OFF**，再选择 **Import WPS**。
3. 等待 **Saved; restart to test**。导入过程中不换卡。
4. 按原项目流程冷启动，再执行 MENU 前置加载步骤：冷启动后约 10 秒内先进入原生 MENU，如有 NTSC 提示先确认；停留一段时间后回 HUD，触摸释放，随后释放按键并按 MENU＋AEL 约 0.6 秒打开悬浮菜单。停留时间没有已证明的固定秒数。
5. 机身「音频信号」沿用既有测试设置“开：除电子快门以外”。先选 SINGLE，再按需要选择循环或 AUTO。

相机端读取卡上包时会核对介质身份、读取两遍并逐字节比较。验证后由工作线程保存到 `/tmp/A9WPS0.DAT` 与 `/tmp/A9WPS1.DAT` 双槽记录；此处 `/tmp` 是本项目确认的 nflasha10 持久区域。保存要经历 fsync、关闭、重开和完整回读验证。

存储外壳为 512 字节头加实际 A9W：魔数 `A9WSTORE`、版本 1、总长、generation、包长度、`COMT` 标记和包／记录摘要。四槽记录总长为 84,032 字节。完整有效记录本身是提交依据；破损／半写记录不能被选为当前记录。双槽用于恢复和选择有效版本，不宣称 VFAT 在任意掉电点具有原子提交保证。

冷启动 helper 从持久记录读包，在 `/tmp_bt` 的 RAM 区准备选中资源，并通过运行期绑定供原生声音路径使用；不是把自定义声音直接刷入原厂 `/usr` 分区。活动包路径是 `/tmp_bt/a9-wps-active.a9w`。这也是导入后要求重启的原因：保存成功不等于当前进程的声音缓存已经重载。

## 9. 质量检查、排错与复现记录

先检查编码长度和包结构，再听最终反解 WAV。重点听首个瞬态是否被裁掉、归一化是否过响、是否削波、循环前缀末尾是否突然跳变、padding 是否在重播时暴露、单次资源尾部是否自然。

| 现象 | 优先检查 |
|---|---|
| packer 报长度错误 | 是否误用 `shutter` 制作 WPS1；是否只保存有效帧而未补齐 |
| SDS 帧头错误 | 输入是否其实为 RIFF WAV、裸 s16 PCM 或其他 ADPCM |
| A9W 哈希错误 | V2 摘要偏移是否仍使用旧 176；描述符和 payload 是否一起更新 |
| 导入失败 | 卡路径、卡槽、精确包长、版本、介质稳定性及剩余存储 |
| 已 Saved 但声音没变 | 是否完成冷启动、菜单加载及原生音频设置；不能仅靠重新复制卡内文件重载 |
| 连拍节奏或 AUTO 间歇异常 | 既有调度周期、回调和模式查询，与素材编码问题分开判断 |
| Wi-Fi 关闭提示变成自定义声音 | WPS4 共用 APP0x32 的已知行为 |

每次制作保留：有权使用的原始素材、转换后的 24 kHz PCM16 WAV、编码参数、原始与最终 SHA、四份 SDS、反解试听 WAV、A9W、`conversion.json` 和软件版本。不要把原 WMA、私人录音或本机路径未经处理提交到公共仓库。

本次离线验证使用合成音和格式夹具，不附带私人快门声。校验、PC 解码试听、C 解析器通过与实际相机音量／接缝验收是不同证据；本次不新增或要求机身测试。
