## R15NH 部署方法

| 阶段 | 输入与输出 | 相机操作 |
| --- | --- | --- |
| 读取与备份 | 保存本机完整 nflasha15、四份 CFG、两张 LUT 和身份记录 | 只读 |
| 识别版本 | 校验同会话备份，识别原厂、R8、R9、R9.1、R10、R11、R12；保存识别证据 | 无 |
| 本地修补 | 根据识别结果选 R12P 差分补丁，复用 R12 的字节替换算法，在本机备份上生成候选并校验摘要 | 无 |
| 写入 | 先校验已识别、已修补证据；重新读取现场，核对同机身份、配置和分区，再用 FF01 一次写入及完整回读 | 完整 300 MiB 写入 |
| 回滚 | 使用同机原始分区备份及配套配置、LUT 恢复并核对 | 完整分区及配套记录恢复 |

软件不分发完整 R15NH 分区镜像。七套来源分别使用约 399–572 KB 的差分补丁，修改约 0.95–1.65 MB 的数据；源镜像、补丁统计和重建结果见 [r15nh-source-validation.json](r15nh-source-validation.json)。正式来源的重建目标 SHA256 均为 `704d9401fb8f63823ffde6a8812eda38ae27d81d6432bf8332cdad95e46233da`。只对已明确列出的 ext2 生命周期字段进行规范化，其他未知变化拒绝。

## V8 与回滚

V8 使用正式完整包的原始载荷；每次安装前在原生连接中重新核对 R15NH 文件及配置。载荷写入和回读完成后才切换 preload。V8 回滚恢复原 preload 并保留载荷；活动 V8 会阻断 R15NH 回滚，须先回滚 V8 并冷重启。重复部署不应覆盖第一次安装的回滚来源。

两个模块分别保存回滚来源。读取、识别或修补后的派生记录不能冒充另一模块的安装备份。通信结果不明时停止并保存完整或部分材料，不自动重试写入。

最终全套 **374 项通过，零失败、零跳过**。日志见 `verification/native-final-tests.log`。其中完整流程测试使用真实 R12 归档分区，并改变已允许的生命周期字段，依次执行备份、离线识别、真实差分修补、模拟 FF01 写入及回读、配对回滚；最终恢复原始备份。测试中的相机边界为替身，没有连接相机。
