# v1.9.1 · V8 兼容已知菜单库段长度变体

修复 1.9.0 在 R15NH 已部署时，因历史实机菜单库变体报 `No complete recognized five-file release`、阻止 V8 部署的问题。

- V8 前置检查同时接受标准菜单库，以及完整 SHA256 为 `07ffd8df517022d9e661240082170ea013023fdeb76156b5510c702bc19fed9e`、长度 10,913,344 字节的已知变体。
- 变体与标准库仅在 ELF 文件偏移 `0x64、0x65、0x68、0x69` 相差四字节：R-X PT_LOAD 的 `p_filesz`、`p_memsz` 从 `0x8c7e78` 变为 `0x8c7dfc`。先核验变体完整 SHA，再仅在电脑内存中的比较副本恢复这两个字段，并再次核验标准 SHA；不会改写机身菜单库。
- 仅调整 V8 的依赖识别。其余四个 R15NH 文件、模块不可变前缀及对象、四 CFG、两 LUT、前后稳定读取、菜单来源和回滚身份校验全部保留。未知变体及任何额外字节修改仍拒绝。
- 状态显示「菜单库：标准版」或「已知段长度变体（兼容）」。部署会话保留机身实际指纹，不用规范化副本覆盖证据。

原生 Windows 界面与 USB 继续基于 v1.8.2。R15NH 的读取机身备份、离线识别与差分修补、FF01 完整分区写入流程不变，未扩大 R15NH 分区修补源白名单；V8 相机载荷和回滚格式不变。227 个 A9P 滤镜、卡目录与许可继续随版本提供。

## 从 1.9.0 更新

下载 `A9Tool-1.9.1-Windows-native.zip` 或单独的 `ILCE-9_Slog_Project.exe`。使用新程序并保留原 `sessions` 目录及回滚来源。在 V8 页读取状态后部署即可，无需因为上述已知菜单库差异重新刷入 R15NH。V8 部署完成后的冷启动与原使用说明仍适用。

该版本依据既有实机文件指纹和四字节对比证据完成兼容修复；发布前执行离线回归和冻结 EXE 自检，未新增相机连接或实机测试。字段变化的来源没有因本次兼容更新被认定。

381 项离线测试全部通过，冻结 EXE 自检确认标准库与已知变体均通过依赖识别、77 项 Fn 功能表及六个原生选项卡可构建、38 项内置发布资源完整。具体范围见 [验证记录](../verification/v1.9.1-validation.json)。
