# 修复：未预期的问题不再只说「未预期」

远端反馈里只有一句「遇到未预期的问题」，没有任何可供定位的信息——异常类型、消息、卡在第几帧，全被吞掉了。这一版把这些都交出来。

## 问题

程序把异常翻译成一句给人看的话：命中已知故障就给处理建议，没命中就退回一句通用的「遇到未预期的问题」。这个设计对已经见过的故障有效，但对没见过的那种，等于什么都没说。

那位用户的日志停在：

```
正在完整读取当前分区（约 300 MB，需要几分钟）…
遇到未预期的问题。请把窗口下方日志整段复制下来。
```

`/dev/nflasha15` 的 300 MiB 读取过程中，可能抛出的异常有五种以上：超时、驱动层 USB 错误、读到空包、应答分帧对不上、文件通道一个字节都没给。它们**一条都没有对应的提示**，全部落进那句通用文字，于是无从判断是哪种。

## 现在会看到什么

每条报错后面都跟一段「技术细节」：

```
遇到未预期的问题：这不是程序认识的已知故障，没有现成的处理建议。
请把窗口下方日志整段复制下来，尤其是下面「技术细节」那几行……

技术细节：
OSError: Invalid or empty service response
    Service USB read: phase=padding drain, frame=412, function=0xff01,
      sequence=3, declared_size=314572800, response=0, payload_received=13500416; no retry
    分区读取中断，已收到 13,500,416 字节；现场保留在 ...\sessions\menu\backup_20261117_203012_ab12cd34
    位置：usbdev.py:281 _readAll()
```

四行分别说明：异常是什么、USB 传输停在哪个阶段第几帧、已经收了多少字节、代码在哪一行。

已知故障（Zadig、没找到相机、机型不符等）仍然先给原来的处理建议，再接同样的技术细节。

## 顺带修的两处

- **超时消息写错了**：分区读取的时限是 900 秒，但报错一直写「30 seconds」。现在用真实预算。
- **超时有了自己的提示**：说清楚程序已停止、没有重试，以及「每次都在同一处停下就先换线换口」。

## 找不到 sessions 文件夹

这一版启动时就把会话目录的完整路径写进日志，每次备份/写入/回退开始前也会再写一次。之前很多人把 exe 放在下载目录或复制过一份，然后去另一个位置找 `sessions`，自然是空的。

## English

**Fixed: an unexpected failure now says what actually failed.**

The error translator turns exceptions into one actionable sentence. Known failures got advice; everything else got a generic "something unexpected happened" and nothing else — which is useless for the failures nobody has seen yet.

Every message now ends with a 技术细节 block: the exception type and message, the note the USB layer attached (transfer phase, frame number, bytes received), how many bytes of the partition had arrived, and the innermost code location. Known failures keep their advice and gain the same block.

Also fixed: the partition-read timeout message said "30 seconds" while the real budget is 900; a timeout now has its own hint.

The window also prints the session directory at startup and before every backup/write/restore, because "sessions is empty" usually means the exe was run from somewhere else and the folder being inspected is not the one in use.

285 tests. Version 1.8.0 → 1.8.1.
