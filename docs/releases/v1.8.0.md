# 强制回退：用官方更新包整机恢复

把相机自报的固件版本改成 5.00，让 Sony 官方 6.00 更新包再刷一次，整个固件回到原厂。

## 这次加了什么

**「强制回退」选项卡**（第五个）。原来的「⑥ 回退」只能把 `/dev/nflasha15` 写回你当初读出来的那一份；如果那份备份本身不是原厂，或者你要的是一次和出厂一致的干净固件，它做不到。这个选项卡改走另一条路——让 Sony 自己的更新包重写固件。

**它改的是什么**：`/setting/updater/dat4`，2 个字节，小端 BCD 的版本串。这不是副本，它就是相机「设置 → 版本」显示值的来源。之前实机验证过：把它写成 5.00 后，所有要求 6.00 的服务模式连接都被拒，说明读的就是这里。

官方更新器只在「包版本高于机身自报版本」时才肯刷，所以写成 5.00，6.00 的包就又能装了。更新会重写 `nflasha15`（/usr）、`nflasha3`、`nflasha5`、`nflasha7`。

## 怎么做

1. 「① 读取版本」→ 确认是 6.00（`dat4 = 00 06`）
2. 「② 写入 5.00」
3. 正常关机、拔 USB、取下电池约 10 秒、装回开机
4. **相机 MENU → 设置 → 版本，确认显示 5.00。** 还是 6.00 就说明没写进去，别往下走
5. **把相机的驱动换回 Windows 的「USB 大容量存储设备」**（官方更新程序认不出 libusb）：
   设备管理器 → 展开 **libusb-win32 devices** → 右键 `ILCE-9` → 更新驱动程序 →
   浏览我的电脑以查找驱动程序 → 让我从计算机上的可用驱动程序列表中选取 →
   勾选「显示兼容硬件」→ 选中「USB 大容量存储设备」→ 下一步
6. 连电脑跑官方 6.00 更新程序，走完
7. 更新结束后版本自动回到 6.00，创意外观 LUT 等分区改动全部消失

更新期间请接电源或保证电量充足，中途绝不能拔线。

## 已实机验证

2026-11-17，项目自己的机身：写 5.00 → 官方 6.00 更新包正常跑完 → 版本自动回到 6.00。所以更新成功之后不需要再手动把版本号改回来。

## 一个要提前说清楚的

官方 6.00 包里带着一份工厂 `Backup.bin`（1,090,266 字节，`0110_backup/…/CX79900_UC2.bin`），`endupdate.sh` 收尾时会把它拷到 `/setting/Backup.bin`。所以 **Fn 槽位、5 GHz 那个字节、4:3 参数很可能也一起回到默认**。

这一点只在脚本层面确认过，没有在机身上逐项核对。如果更新后发现某项没变，用「Fn 功能」和「解锁 5GHz WiFi」各自的恢复按钮处理即可。

## 安全设计

- 只写 `/setting/updater/dat4`：路径、载荷长度（必须 2 字节）、写入内容（必须等于本次事务声明的值）都在白名单里卡死
- 一次会话只允许一次写入
- 写前把原值落盘到会话目录，写后逐字节回读核对；不一致就停下并保留现场
- 这个选项卡在相机报 5.00 时也能连上（其余选项卡仍然要求 6.00），所以写了 5.00 又改主意时，还能点「③ 写回 6.00」恢复

## 其它改动

| 改动 | 说明 |

## English

**Force rollback: let Sony's own package restore the firmware.**

A fifth tab changes the version the body reports (`/setting/updater/dat4`, two bytes) from 6.00 to 5.00, which makes the official 6.00 updater willing to install again. That update rewrites `/usr` and the other firmware partitions, so the Creative Look LUT and every other partition change is gone. When it finishes, the updater writes 6.00 back on its own — verified on hardware on 2026-11-17.

Before running the updater, switch the camera's driver back from libusb-win32 to Windows' "USB Mass Storage Device": Device Manager → Update driver → Browse my computer for drivers → Let me pick from a list of available drivers → Show compatible hardware → USB Mass Storage Device.

Caveat: the official package carries a factory `Backup.bin` and `endupdate.sh` copies it over `/setting/Backup.bin`, so Fn slots, the 5 GHz byte and the 4:3 parameters are very likely reset as well. Confirmed at script level only.

The write is pinned to one path and two bytes, one write per session, with the old value saved to disk first and a byte-for-byte readback afterwards.
