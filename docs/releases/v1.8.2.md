# 修复：libusb 的「不支持这个操作」现在会说明它是谁、卡在哪

远端反馈的原始报错是：

```
NotImplementedError: Operation not supported or unimplemented on this platform
    位置：libusb1.py:600 _check()
```

两行字，没说是谁抛的、也没说卡在传输的哪一步。

## 这是什么

`libusb1.py:600` 是 pyusb 的 `_check()`。它把 libusb 的返回码翻译成 Python 异常，其中 **-12（`LIBUSB_ERROR_NOT_SUPPORTED`）被翻成了 `NotImplementedError`**——一个看起来像"程序写错了"的类型，实际上描述的是驱动层。

而 PMCA 的 `UsbBackend.read()` 只把 `usb.core.USBError` 转成自己的 `GenericUsbException`，`NotImplementedError` 不在其中，于是原样穿透到界面上。

## 现在的提示

```
USB 驱动层回了一个「不支持这个操作」（libusb -12，LIBUSB_ERROR_NOT_SUPPORTED）。
在 Windows 上通常是两种情况之一：
① 相机这个接口没有绑定 libusb 兼容的驱动——用 Zadig 重新装一次
   （Options → List All Devices，选中相机那一项，装 libusb-win32），装完拔线重插；
② 传输中途相机掉线或者被重置了——关机重开，换一根线、换一个 USB 口再试。

技术细节：
NotImplementedError: Operation not supported or unimplemented on this platform
    libusb 返回 -12（LIBUSB_ERROR_NOT_SUPPORTED）：……
    Service USB read: phase=payload, frame=412, function=0xff01, sequence=3,
      declared_size=314572800, response=0, payload_received=13500416; no retry
    分区读取中断，已收到 13,500,416 字节；现场保留在 C:\...\sessions\menu\backup_...
    位置：libusb1.py:600 _check()
      ← menu_deploy.py:227 read_partition()
```

三处改动：

- **USB 层认出这个错误码**，在异常上附一条中文说明，写清 -12 的两个常见原因。
- **技术细节多给两帧本程序的栈**。原来只显示最内层，而最内层几乎总在 vendored 的 `libusb1.py` 或 `__init__.py` 里——指向 pyusb，而不是指向工具当时在做什么。现在会补上 `usbdev.py` / `menu_deploy.py` 这些自己的帧。
- 错误翻译表里加了这个错误的条目，所以它不再落进「未预期的问题」。

## 还有一件事没定论

这条报错发生在**服务模式认证已经成功之后**——认证本身就要走好几个 USB 包。所以"驱动完全没装好"解释不了一切，更像是**传了十几 MB 之后接口才拒绝传输**。

`phase=` 那一行能分清：如果停在 `response header`，说明第一包就没过去；如果停在 `payload`，说明是传到一半断的。把完整那段发过来就能定。

## English

**Fixed: libusb's "operation not supported" now says what it is and where it hit.**

The reported error was `NotImplementedError: ... 位置：libusb1.py:600 _check()` — two lines that name neither the caller nor the step the transfer died on.

`_check()` is pyusb translating libusb return codes, and it maps **-12 (`LIBUSB_ERROR_NOT_SUPPORTED`) to `NotImplementedError`** — a type that reads like a programming mistake. PMCA's `UsbBackend.read()` only converts `usb.core.USBError`, so this one escaped untouched.

Every message for this failure now names the code, gives the two usual causes (interface not bound to a libusb-compatible driver; device dropped or reset mid-transfer), and the technical block adds up to two frames from this package instead of only the innermost frame in vendored pyusb.

Open question: authentication succeeded before this error, and authentication is itself USB traffic — so a completely missing driver does not explain it. The `phase=` line will: `response header` means the first packet never went through, `payload` means it died part-way.

287 tests. Version 1.8.1 → 1.8.2.
