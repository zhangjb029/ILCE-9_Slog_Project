## 1. 交付内容与修改范围

| 源码入口 | 修改目标 | 本机首次修改 | 作用 |
| --- | --- | --- | --- |
| `python -m a9tool.flash` | Backup 属性 `00020008`，内部表索引 `0x45` | `1 → 0` | 取消上层强制禁闪规则；单独使用时只确认菜单恢复可选，仍不能电子引闪 |
| `python -m a9tool.flash_av` | Backup 属性 `0003000B`，属性内部字节偏移 `0xAD` | `0 → 1` | 通过已定位的原厂 AV 电子快门闪光资格检查；要求第一项已为 0 |

`0x45` 是表项编号，`0xAD` 是属性内部偏移；都不能当作整份文件或分区的裸偏移使用。第一项通过原厂服务写入完整 1024 字节属性，仅允许改变索引 `0x45` 的值；第二项写入完整 256 字节属性，仅允许偏移 `0xAD` 一个字节不同，保留现场读取的其他 255 字节。脚本不拿工厂模板覆盖本机配置。

两项均调用原厂 `writeBackup(PID, 完整属性)` 和 `saveBackup(0)` 持久保存。已定位的主配置是 **`nflasha2` 挂载的 `/setting/Backup.bin`**；SAVE 还可能涉及原厂副本和元数据处理，不能理解为只写某个物理扇区。

| 原厂消费者 | 代码位置 | 本工具是否替换该代码 |
| --- | --- | --- |
| 上层配置规则 | `nflasha15` 的 `lib/libObj.so` | 否 |
| AV 闪光资格判断 | `nflasha3` 的 `av-cam.bin`，运行路径 `/system/av-cam.bin` | 否 |

原厂加载和配置回调会更新运行时对象。工具没有任意地址 RAM 写入、程序钩子、整分区刷写或自动拍摄逻辑；这不表示配置写入不会改变 RAM 中的运行状态。`0003000B` 的原厂回调可能在 SAVE 或重启前立即生效。

**第一项的影响不止菜单。** 索引 `0x45` 同时影响普通快门参数 `9AAF` 和间隔拍摄快门参数 `A016/PARAMID_INTERVAL_SHUTTER_TYPE` 的已识别禁闪规则。原厂规则会把间隔电子状态 `2E88` 转为仍使用电子快门、但强制禁闪的 `2E89`；设为 0 会跳过该转换，不会主动把已经存在的 `2E89` 复位。间隔拍摄不属于本次成功交付范围，也未证明所有间接影响均已穷尽。

`python -m a9tool` 仍是原 PP/Fn 图形界面。本文两项闪光配置使用独立命令行入口；不要用原图形界面的“恢复全部原厂”代替本文的闪光配置恢复。

- 仅使用 **ILCE-9 / 6.00**；不适用于 A9 II 或其他机型、固件。脚本检查机型、版本及机身身份指纹。

- 使用原先成功连接的数据线和端口，只有一台相机连接，关闭其他占用相机的程序。正常连接入口为相机“大容量存储”；服务模式是另一个 USB 身份，两者的驱动配置沿用原项目。

## 4. 检查与启用

### 4.1 先检查当前两项值

```powershell
python -m a9tool.flash_av status
```

这会识别机身、进入并认证服务模式、保存完整只读 Backup 快照，打印上层索引 `45` 和 AV 偏移 `AD` 的值。**“只读”指不写 Backup 属性、不请求 SAVE，仍会与相机通信并切换模式。** 两个入口省略动作时也都默认为 `status`。

| 读值 | 含义与处理 |
| --- | --- |
| `45 = 1`，`AD = 0` | 本机首次记录的两项禁闪配置；启用时按下面顺序分别修改 |
| `45 = 0`，`AD = 0` | 第一项已开放，只需在确认操作条件后执行第二项 |
| `45 = 0`，`AD = 1` | 两项已到目标值；当前已成功配置的机身不需要重复 apply |
| `45 = 1`，`AD = 1`，或出现格式、身份、回读异常 | 不按已验证组合使用；保留输出和日志，先核对来源与恢复材料 |

每条命令须等到进程退出、返回 PowerShell 后再进行下一步，不同时运行多个入口。

### 4.2 开放第一项：上层规则

仅在索引 `45 = 1`、且准备启用时执行：

```powershell
python -m a9tool.flash apply
```

记录输出的 `Journal:` 完整路径。得到 `SAVED_AND_READBACK_VERIFIED` 后，等待脚本退出；保持热靴空置，正常关机、拔下 USB，再开机确认机身正常。重新连接并用 `flash_av status` 核对 `45 = 0`。

单独完成这一步并不意味着能引闪：既有实机结果是菜单可选，但 HUD 仍禁止闪光。

### 4.3 开放第二项：AV 资格条件

确认 `45 = 0`、热靴附件已经拆下后执行：

```powershell
python -m a9tool.flash_av apply --flash-detached
```

`--flash-detached` 是操作者对热靴空置的人工确认；软件不会自动检测，也没有向相机新增测试开关。`flash_av` 不会代为修改第一项，发现 `45` 不是 0 就停止。

保存本次 `Journal:` 路径。得到 `SAVED_AND_READBACK_VERIFIED`、脚本退出后，保持热靴空置，正常关机、拔 USB、再开机，检查菜单及取景正常。需要复核保存值时重新连接运行 `flash_av status`，应为 `45 = 0`、`AD = 1`。

配置复核结束、脚本退出并正常关机断开 USB 后，才在相机和灯均关机的状态下安装附件。已确认的功能范围是普通电子单张；使用慢于 `1/160 s` 的曝光，如 `1/125 s`，可避开当前已报告的较快快门黑边区域，但仍须检查实际照片。不要据此把电子连拍作为已完成能力使用。

源码终端仍可能打印试验初期的“物理引闪尚未验证”等固定文字。它表示程序本身不检测物理输出；当前实机成功范围以本文件第 2 节为准，不能从保存成功提示推断额外能力。

## 5. 恢复两项配置

恢复会写入相机，同样先在机身与灯均关机时拆下热靴附件，再连接。顺序为 **先恢复 AV，确认完成后再恢复上层规则**。各自使用首次实际改变该项时的 `apply` 日志。

先恢复 AV。下面输入的是日志文件完整路径，不是会话文件夹：

```powershell
$avApplyJournal = Read-Host '输入首次实际 0→1 的 flash_av_apply journal.json 完整路径'
python -m a9tool.flash_av restore --flash-detached --journal $avApplyJournal
```

确认事务成功并等待脚本退出后，正常重启、重新连接，用 `flash_av status` 核对 AD 已回到该日志记录的原值；本机对应原值为 0，上层规则仍为 0。失败或出现恢复冲突时停下核对，不继续后一步。

再恢复上层规则：

```powershell
$menuApplyJournal = Read-Host '输入首次实际 1→0 的 flash_apply journal.json 完整路径'
python -m a9tool.flash restore --journal $menuApplyJournal
```

确认成功、脚本退出并正常重启后，可重新连接用 `flash_av status` 核对。本机原始两项值为 `45 = 1`、`AD = 0`；这只说明这两项配置恢复到记录原值，不等于全机恢复出厂设置。

恢复要求原始快照和 SHA256 校验有效、属于同一机身和固件，且当前待恢复的**完整属性**与日志中的原值或目标一致。有其他变化时工具会拒绝覆盖。它只恢复对应属性，不整份回灌 Backup。

**不要使用 `ALREADY_AT_TARGET_NO_SAVE` 的后来日志冒充首次修改前基线。** 若它记录的是 `1 → 1` 或 `0 → 0`，恢复该日志也不会回到更早的原始配置。恢复依赖机身仍能稳定进入服务模式，无法修复硬件损坏或保证救回失联机身。

## 6. 事务结果与异常处理

| 输出状态 | 说明 |
| --- | --- |
| `READ_ONLY_COMPLETE` | 读取和本地备份完成，没有写 Backup 或请求 SAVE |
| `SAVED_AND_READBACK_VERIFIED` | 保存调用返回，目标完整属性回读一致；不代表物理引闪或硬件安全已验证 |
| `ALREADY_AT_TARGET_NO_SAVE` | 现场已是目标，没有写入或 SAVE；本次日志不能代替更早的原始基线 |
| `FAILED_REVIEW_REQUIRED`，或其他异常退出 | 操作停止，需要保留日志检查最后阶段；不能仅凭异常断定相机完全未接收写入 |

写入流程先保存本机完整快照和日志，再复核现场值，经独立报文白名单执行一次目标写入，完整回读一致后才请求一次 SAVE，并再次完整回读。第二入口还核对第一项在过程中未改变。异常时没有自动重试或自动回滚。

连接失败时先检查机身 USB 模式、既有驱动及同一端口，不通过反复 apply 解决。切换服务模式失败时，工具可沿用一小时内有效的身份凭据；过期凭据不能绕过身份检查。USB 驱动安装细节沿用项目 README，不能把 `054C:0994` 充电／HID 身份当作本工具所需的服务设备。

发生黑屏、卡死、异常连闪、异常发热或 USB 反复断连时停止测试，保留完整输出和会话目录。仍在写入或 SAVE 时不要主动拔电；连接异常后不要盲目重复写入。只有服务接口仍能稳定连接且恢复材料核验通过时，才使用上述恢复入口。

历史日志中的 `physical_trigger_verified=false` 等字段只记录工具当时自动验证的范围。后续实机观察单独记入报告，**不回改原始日志或备份**。
