## 改什么

| 项目 | 组合试验要求 | 本入口行为 |
| --- | --- | --- |
| `00020008` 内索引 `0x45` | 0，上层不施加电子快门禁闪 | 只读验证；不是0就停止，不自动改第一处 |
| `0003000B` 内字节偏移 `0xAD` | 1，通过已定位的AV电子资格检查 | 仅允许0/1转换；保留同一机身该属性的其他255字节 |

用户之前已完成第一项，菜单恢复可选但电子快门仍不引闪。新增入口在此基础上只写第二项，因此不存在两个属性写到一半的组合事务。服务协议实际写入整项256字节；逻辑差异只能是偏移AD这一个字节。属性来自当次机身读取，不能用工厂模板代替。

这不替换av-cam.bin或Darwin等程序代码，不直接刷写分区镜像、不任意地址写RAM，也不安装钩子、额外机身测试开关或发送拍摄指令。两项配置通过原厂Backup服务持久保存至`/dev/nflasha2`挂载的`/setting`，主配置文件是`/setting/Backup.bin`；原厂加载和回调会更新运行时RAM对象。因此，先前“不修改nflasha分区或RAM”的表述不准确。`--flash-detached`只是电脑端的人工状态确认，不是机身内新增逻辑，也不是软件已检测热靴空置。

### 配置存储与代码所在位置

| 修改 | 持久配置位置 | 读取配置的原厂代码（本试验不修改） |
| --- | --- | --- |
| 上层电子快门禁闪规则，1→0 | `nflasha2`的`/setting/Backup.bin`，属性`00020008`内部表索引`0x45` | `nflasha15`中的`lib/libObj.so` |
| AV电子快门闪光资格条件，0→1 | 同一配置数据库，属性`0003000B`内部字节偏移`0xAD` | `nflasha3`中的`av-cam.bin`，运行路径`/system/av-cam.bin` |

`0x45`是表索引；`0xAD`是该属性内部偏移。两者均不是整份Backup.bin或分区的裸偏移。脚本调用`writeBackup(PID,完整属性)`及`saveBackup(0)`，不直接按文件偏移修改；新增flash_av入口只写第二项。原厂backup.ko还包含主/副文件处理及`/Backup.bak`字符串，当前未穷尽每种SAVE条件下的副本与元数据写入，不声称只触及一个物理文件或一个扇区。

分区依据为本地A9 6.00原厂文件：`analysis/a9_v600/firmware.tar_unpacked/0700_part_image/dev/nflasha15_unpacked/bin/common.src`第6/8行定义`/setting`与`/dev/nflasha2`；同目录`udtrbody.bin_unpacked/bin/endupdate.sh`第44行执行该挂载，第79行写入`/setting/Backup.bin`。原厂`kmod/backup.ko`也包含该完整路径。代码文件分别核对自`nflasha15_unpacked/lib/libObj.so`与`nflasha3_unpacked/av-cam.bin`。

## 硬件风险判断

**结论：有依据做受限实验，但无法给出损坏概率，也无法把它评为已证明低风险。若不能接受再次损坏机身或闪光灯的后果，应止于离线研究。**

支持开展有限试验的证据：

- 两项都选择A9原厂已有分支；AD非零不会无条件强置FireReq，已验证的其他抑制条件继续有效。
- 相同人工输入下，电子快门AD=1与机械快门的完整34字节拍摄命令、12字节周期数据逐字节一致。48组载体对照、384组下层模式/报文/停止位置对照通过。它是有利证据，但不是整机或电气等价证明。
- 当前确认的AD直接消费者属于资格判断及状态打包。没有在这些已核查路径中发现该字节直接决定供电电压、GPIO方向或镜头马达控制。

仍不能排除的风险：

- AD全部间接消费者、真实电子单张的完整异步调度和最终热靴输出尚未穷尽。请求被放行后，可能进入原厂A9电子快门正常配置不会执行的组合路径。
- `0003000B`为attr=8，原厂注册回调会将完整属性复制到AV运行对象。**不能认为“只要不SAVE/不重启就还没生效”。** 写入时必须先拆下热靴附件。
- 回读成功只证明配置字节，不证明运行时正确；出现崩溃、无法启动或服务接口失联时，恢复脚本可能无法使用。
- 用户先前LA-EA5试验已有IC5700损坏并更换的经历。那次项目永久结案；本次没有证据证明会复现相同故障，也没有证据证明原厂分支和单字节修改能免除硬件损坏。
- 低闪光功率和少量单次测试用于控制试验条件。**它们不能保证机身热靴接口/控制芯片不会受损。** 此处不将曝光是否均匀作为成功条件，但也不能把“忽略曝光时序”推广为忽略电气驱动行为。

## 附件与首轮条件

用户报告附件为神牛Godox iT30、支持索尼TTL，HSS/无线/连续闪光均可关闭。官方对应索尼版名称是 **iT30Pro S**；操作前核对灯体型号后缀。官方说明书的相机兼容列表包括α9，但这是原厂相机使用条件下的兼容说明，不覆盖本试验。

建议首轮使用这支灯的**机顶M手动闪光，1/128功率**；关闭HSS、Multi频闪、无线主控/从属和S1/S2光控。支持TTL的附件使用M模式仍不等于单触点灯，不能据此声称绕过索尼附件通信。先检验是否产生一次正常闪光；TTL曝光控制留待这个结果明确后另行验证。

机身使用照片M曝光、普通单张、明确选择电子快门、强制闪光，快门可设1/10秒作为固定观察条件。关闭包围、间隔及连拍，避免首次叠加其他拍摄流程。不得将A9III的全域快门同步说明或闪光时序设置套用到A9。

神牛官方依据：

- [iT30Pro官方说明书](https://www.godox.com/Downloads/Godox_iT30Pro-S.pdf)，PDF第9页：装卸前机身与灯均关机；第12页：M模式1/128至1/1及S1/S2；第32页：Sony兼容列表含α9。这里页码为PDF物理页，含封面。

## 分阶段操作

先将相机和闪光灯均关机，拆下闪光灯/引闪器，再用原来的数据线连接机身。仅保持正常原厂镜头或机身盖，不接已结案的LA-EA5试验附件。

```powershell
Set-Location -LiteralPath '<项目目录>'
$env:PYTHONPATH='src'
python -m a9tool.flash_av status
```

预期上层索引45=0、AV偏移AD=0，并产生`READ_ONLY_COMPLETE`与完整备份。其他值或异常先停下核对。`status`会切换服务模式并读取；“只读”指不写Backup/不SAVE，不代表完全无设备交互。

**第一阶段：空热靴启用与恢复演练。** 接受上述未定量硬件风险后，保持热靴空置：

```powershell
python -m a9tool.flash_av apply --flash-detached
```

保存打印的`Journal:`绝对路径。仅`SAVED_AND_READBACK_VERIFIED`表示这次保存和完整回读成功。脚本退出后正常关机、拔USB、再开机，检查菜单和取景是否正常。然后用`status`核查45=0、AD=1。读回正确也不表示运行时和硬件安全已验证。

用本次实际日志先做一次空热靴恢复演练：

```powershell
python -m a9tool.flash_av restore --flash-detached --journal '本次flash_av_apply的journal.json完整路径'
```

正常重启后，用`status`确认AD回到本次原值0、菜单规则仍为0。这个演练只证明正常可连接状态下能恢复，不能证明崩溃/损坏后能恢复。若首次apply已经显示`ALREADY_AT_TARGET_NO_SAVE`，它不是原厂0值的恢复基线；应找最早实际0→1的日志，不要把后来1→1的备份误当原厂。

**第二阶段：一次带灯观察。** 仅在空热靴启用、重启和恢复均正常后，再次apply并保存新日志；重新启动、核对两项值。机身和灯均关机后安装已确认的索尼版灯，再按前述M/1/128条件开机。先看附件是否识别、HUD是否仍禁闪、是否有异常自动闪光。无异常才按一次快门。

首轮记录：是否返回取景、HUD图标、是否可见闪光、照片是否出现闪光照明、是否异常连闪、机身与灯是否响应。没有闪光或HUD仍禁闪时不连续重试、不增加功率、不切HSS或强置更多底层参数。停下保存结果和日志，继续定位。

若出现黑屏、卡死、异常连闪、异常发热、异味或USB反复断连，立即结束试验；按正常方式关机并在关机后拆下附件，不反复上电“碰运气”。如果当时仍处于写入/SAVE阶段，不主动拔电或中断传输；保留日志明确最后一步。只有机身仍能稳定进入服务模式才运行恢复，不通过反复刷写追赶恢复窗口。

首轮结束后建议恢复AD到原值0，再讨论是否继续。不得把一次引闪成功当作稳定可用或硬件安全的验证。

## 恢复范围

AV恢复只还原本次记录的`0003000B`，不改变上层索引45。完整回到两处原厂禁闪，需要先恢复AV，再用原来`python -m a9tool.flash restore --journal ...`恢复第一处。

已确认的第一处0/1实验原日志是：

```text
<项目目录>\sessions\flash\<会话目录>\journal.json
```

只有同一机身、日志原始快照通过校验、当前整项仍与日志原值或目标一致时才能恢复；冲突即停止，不覆盖未知的新设置。恢复功能不能修复硬件损坏，也不是救砖方案。

## 验证范围

写前完整快照与SHA256落盘，两项现场重读；一次精确写入、两项回读、一次SAVE、再次两项回读。错误不重试、不自动回滚；不开放其他PID写入、整Backup、RAM、固件或保护命令。
