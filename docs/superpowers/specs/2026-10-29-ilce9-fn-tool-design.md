# ILCE-9 功能槽位工具 — 设计文档

日期：2026-10-29
状态：待批准
仓库名：`ILCE-9_Slog_Project`

---

## 1. 这是什么，为谁做

一个面向 **非开发者** 的 Windows 工具，让 Sony A9（ILCE-9，固件 6.00）的用户把机身里存在、但官方界面没有入口的功能，放到 Fn 菜单的槽位上，从而能在相机上直接用。

核心是两项已被实机验证的功能：

| 功能 | 保存值 | 实机结果 |
|---|---|---|
| Picture Profile（图片配置文件） | `0x3A` | Fn1 出现入口，录制画面随 PP 变化，重启后仍在 |
| SLog 显示辅助（SLogDispAssist） | `0x36` | Fn7 显示正常，功能可用，重启后仍在 |

以及另外 75 项从固件跳转表里读出来、**从未在实机上试过**的功能。用户明确要求全部开放。

**为什么做**：现有工具是 Python 命令行脚本，要求用户装 Python、装 USB 驱动、敲命令、读英文报错。这些门槛跟「能不能开 PP」毫无关系，却把 99% 的目标用户挡在外面。这个项目的全部意义就是**把环境门槛消灭掉**。

**成功的标准**：一个从没装过 Python、没接触过命令行的人，照着网页图文，在 30 分钟内让相机上出现 Picture Profile。

## 2. 交付形态

三件东西：

1. **一个图文教程站**（GitHub Pages），中英双语，讲清楚从零到能用的每一步，包括装驱动、点哪里、看到什么算成功、出问题怎么办。
2. **一个 exe**（GitHub Releases 下载），双击打开就是图形界面，不装任何东西。
3. **一个开源仓库**，代码、构建脚本、教程站源码都在里面。

教程站负责讲，exe 负责做。两者分离。

## 3. 目标 / 非目标 / 反目标

### 目标

- 用户全程不接触命令行、不装 Python、不读英文报错。
- 两项已验证功能做到「选槽位 → 点写入 → 重启 → 生效」。
- 任何一次写入都可以一键回到原状。
- 出错时用户知道**下一步该做什么**，而不是看到一堆异常栈。

### 非目标

- 不支持 ILCE-9 之外的任何机型（A9 II、A7 系列一律拒绝）。
- 不支持 6.00 之外的任何固件版本。
- 不做固件修改、不做刷写、不碰更新包。**这个工具只改机身备份参数里的几个字节。**
- 不做自动更新、不做联网、不收集任何数据。
- 不做 macOS / Linux 版本。

### 反目标（即使「能用」也算失败）

- 用户在不知道风险的情况下点了写入。
- 用户在改坏之后找不到回滚路径。
- 用户以为「菜单里出现了」就等于「功能能用」。
- 用户装完驱动后以为相机坏了（Windows 里看不到存储卡了）。

## 4. 约束

### 来自项目历史的硬约束

- **只支持 ILCE-9 / 6.00。** 槽位属性地址 `0x01070BE8`…`0x01070BF3` 这一组只在 6.00 上核验过。exe 必须先读机身型号和版本，不符就停手。
- **一次运行 = 一次写入 = 一次保存 = 断开。** 不给「连续改多个槽位」的能力。每次写入都有独立备份、独立事务记录。
- **写入前必须落盘原值快照和 journal**，先落盘再写。
- **`0x64`（像素转换多重拍摄）已实测会在第一张后卡死、需拔电池。** 保留可写（用户要求 77 全开），但红标 + 二次确认。
- **SAVE(0) 会让 WBI 失效。** 下次冷启动重建，启动变慢，不是故障。
- 不发送白名单外的报文；失败不自动重试、不自动回滚。

### 现实约束

- **exe 未签名。** SmartScreen 会拦，杀毒软件可能报毒。教程必须有专门一节。
- **Zadig 换驱动后资源管理器看不到相机存储卡。** 用完要卸掉驱动才能恢复。
- **第二次驱动安装。** 相机切到服务模式后会出现一个新设备，需要单独再装一次驱动。这是最容易让用户放弃的一步。
- **不能分发 Sony 的固件、密钥、解包产物。** 中文菜单名表来自固件 UI 资源，会在 `NOTICE` 里说明来源与权利归属（见 §9）。

## 5. 用户流程

### 第一次使用

```
1. 打开教程网页
2. 下载 exe（GitHub Releases）
3. 双击 exe → 可能遇到 SmartScreen → 教程讲怎么点「仍要运行」
4. 用 Zadig 给相机装 libusb-win32 驱动（大容量存储设备）
   └─ 相机必须已经在「大容量存储」模式下连上电脑
5. exe 点「连接并检查」
   ├─ 需要切服务模式 → 新设备出现 → 教程讲怎么给它再装一次驱动
   └─ exe 记住凭据，窗口里给「重试」，不用翻文件
6. exe 显示：检测到 ILCE-9 / 6.00 / 序列号指纹
7. 点「开启 PP 放行」→ exe 只写功能覆盖属性 → 提示「请重启相机」
8. 关机重启
9. 再打开 exe → 选 Picture Profile → 选 Fn1 → 写入 → 提示重启
10. 关机重启
11. 按 Fn 键，看见 Picture Profile → 成功
```

**为什么第 7 步和第 9 步要分开、各自重启**：放行位和槽位写入是两次独立事务，各自结束后都会让相机停在服务模式，现有工具每次都是写完就断开。而且「同一个服务会话里先开放行位、紧接着写槽位，槽位是否立即认得新的放行状态」**从来没有验证过**。分成两步、每步重启，是唯一完全踩在已验证路径上的做法。

代价是流程长。这一点在教程里要坦白说明，不要让用户以为一次就能搞定。

### 回滚

```
1. 打开 exe
2. 点「从备份恢复到原状」
3. 选一条记录（exe 自动列出，带时间和改了什么）
4. 写入原值 → 提示重启
```

### 完全撤销

设备管理器 → 找到相机 → 卸载设备 → 勾选「删除驱动程序」→ 重新插上 → Windows 恢复成普通相机。

### 交互规则

- **默认只显示两个卡片。** 77 项藏在「全部功能」折叠区。普通用户不会误点。
- **展开后每项显示：** 中文名（固件原文）、固件符号名、保存值（`0x3A`）、状态标记。
- **状态标记三种：** ✅ 已实机验证 / ⬜ 未验证 / ⛔ 已知会出问题。
- **`0x64` 是 ⛔**，点击写入弹二次确认：「实测会在拍摄第一张后卡死，需要拔电池。确定继续吗？」默认焦点在「取消」。
- **写入成功后整个功能区和写入按钮全部禁用**，窗口只剩「请重启相机」和日志。要再改，关掉重开。
- **写入按钮在写入期间禁用**，防连点。
- **任何失败都在日志区给出「下一步」**，例如：「服务模式没有连上。请回到大容量存储模式，再点一次『连接并检查』。」

### PP 放行位的三种状态

| 状态 | exe 表现 |
|---|---|
| 五个偏移全是 `02` | 显示 ✓ 已开启，`③` 区的卡片可用 |
| 五个偏移都不是 `02` | 显示 ✗ 未开启，`[ 开启 PP 放行 ]` 可用，`③` 区卡片禁用（点了也只提示先开放行） |
| 混合状态（部分 `02`） | 显示 ⚠ 状态异常，**不提供写入**，提示先用「恢复全部原厂」或从备份恢复 |

混合状态不猜，直接停手。

## 7. 安全机制

### 第一层：机型/版本门

启动后第一件事：读机身型号和固件版本。不是 `ILCE-9` + `6.00` 就拒绝所有后续操作，只显示：

> 这个工具只支持 ILCE-9 固件 6.00。你连接的是 <机型> <版本>。其他机型的参数地址不同，强行写入可能损坏相机配置。

### 第二层：写前落盘

每次写入前，把原值快照 + 事务记录写到 **exe 所在目录**的 `sessions/<时间戳>-<随机>/`，先落盘再写。目录里有：

- `Backup-original.bin`：写入前的完整参数快照
- `journal.json`：本次要改什么、原值、目标值、处于哪一步

界面上显示这个路径，用户可以自己备份走。**注意**：PyInstaller `--onefile` 会解压到临时目录，路径必须落在 `sys.executable` 所在目录，不能落在临时目录。

第一次使用时额外保存一份 `baseline/`，供「恢复全部原厂」使用。

### 第三层：回读校验

写完 → 回读 → 确认目标值对上、其余槽位没被碰过 → 才发 `SAVE(0)` → 再回读。任何一步对不上就停，日志说明「机身可能已部分改动，请保留 session 目录」。

### 第四层：回滚

两种粒度：

- **「从备份恢复到原状」**：列出所有 session，选一条就回到**那一次写入之前**的值。只改那一次碰过的东西，不碰整份快照——否则会抹掉用户后来在相机上改的别的设置。
- **「恢复全部原厂」**：用 `baseline/` 把工具碰过的所有属性一次性写回第一次使用前的值。

**链式警告**：如果用户连着改过两次，第二次的「原值」就是第一次改完的结果。恢复第二次只会退回到第一次改完的状态，不是出厂状态。session 列表里要把这一点显示出来（每条记录写明「此记录的『原值』= 上一次写入后的状态」）。

如果当前值和记录的原值、目标值**都对不上**（用户中途在相机上手动改过），恢复**拒绝执行**并说明原因，不猜。

### 第五层：服务模式凭据复用

切换服务模式后出现的设备如果没装驱动，脚本会停在服务模式且拿不到大容量存储设备。exe 会把这次的 Identity receipt 存下来（1 小时有效、同一 USB 物理端口），窗口里给「重试」按钮直接复用，不让用户去翻文件路径。凭据过期就提示「把相机拔掉重插，回到大容量存储模式，再点连接」。

## 9. 分发、构建与许可

### exe

- PyInstaller `--onefile --windowed`，约 15–25 MB。
- 打包进 `src/vendor/` 全部内容 + `src/data/` 全部 JSON。
- 文件名：`ILCE-9_Slog_Project_v1.0.exe`
- 发布到 GitHub Releases，不进 git（`.gitignore` 排除 `dist/`、`build/output/`、`sessions/`）。

### 许可与 NOTICE

- 项目代码：MIT。
- `src/vendor/pmca/`：ma1co/Sony-PMCA-RE，MIT，保留原版权声明。
- `src/vendor/pyusb/`：BSD。
- `src/vendor/libusb/`：LGPL-2.1，动态链接，`NOTICE` 里给上游地址。
- **`a9_fn_chinese_names.json`**：77 个中文名里 64 个来自 Sony 固件的 UI 资源字符串。**决定：照用**，因为用户在相机菜单里看到的就是这些词，换成自己翻的反而对不上。`NOTICE` 里明确写「这些字符串摘自 Sony 固件界面资源，仅用于与相机菜单对应，本项目不主张其权利」。不随包分发任何固件二进制、密钥或解包产物。

### 必须写进教程的坑

1. **SmartScreen 拦截**：更多信息 → 仍要运行。
2. **杀毒软件误报**：说明为什么会被报（要访问 USB 设备），给源码链接。
3. **Zadig 第一次装驱动**：截图，确认选的是相机不是 `VID_054C&PID_0994` 那个输入设备。
4. **Zadig 第二次装驱动**：切服务模式后新出现的设备。
5. **换驱动后看不到存储卡**：正常，不是坏了。
6. **怎么撤销驱动**：设备管理器卸载 + 删除驱动。
7. **菜单出现 ≠ 功能能用**：单列一节。
8. **为什么要重启两次**：解释放行和槽位是两次独立写入。
9. **回滚怎么做**，以及链式恢复的局限。

## 10. 我替你做的决定（读的时候请检查）

| 决定 | 理由 |
|---|---|
| Python + tkinter + PyInstaller，不重写成 C#/Rust | 现有逻辑（PMCA 协议、事务、校验）已验证过，重写等于重新引入风险。tkinter 是标准库，打包简单。 |
| 教程站用纯静态 HTML | 零构建、零依赖、离线可读，GitHub Pages 直接发布。 |
| 只支持 Windows | 用户群和 Zadig 都在 Windows。 |
| `docs/` 同时放教程站和设计文档 | 设计文档公开是好事（透明）。 |
| 严重警告放在卡片上方，不放在启动弹窗 | 启动弹窗会被条件反射点掉。 |
| 不自动检测/下载新版本 | 联网行为增加不必要的信任成本。 |
| 日志区常驻，不可隐藏 | 用户截图求助时，日志就是全部诊断信息。 |
| 一次运行只能写一个槽位 | 用户选定。每次写入都有独立备份，风险面最小。 |
| 「开启 PP 放行」不碰任何 Fn 槽位 | 用户选定。不悄悄霸占人家的 Fn1。**代价：这个组合（只写放行位、不写槽位）从未在实机上单独跑过**——放行位写入和槽位写入各自都验证过，但分开做是新的。教程里对第一批用户要说明这一点。 |
| 中文名用固件原文 | 用户选定。见 §9。 |

## 12. 未解决的问题

1. **只写放行位、不写槽位，是否安全且有效。** 现有 `--apply` 一直是两件事一起做。拆开后，机身会不会因为放行位变了而触发别的重新初始化，**未知**。第一批用户是这个组合的验证者，教程必须说明。
2. **77 项里 74 项全未验证。** 已知 `0x64` 会卡死。其他 74 项会不会有更严重的后果（比如写坏某个配置导致无法开机），**没有任何数据**。这是项目最大的未知风险，必须写在教程首页最显眼处。
3. **服务模式切换的成功率。** 现有脚本在某些 Windows + 驱动组合上会报 `Service device not found`。实测成功率未知，教程要给重试指引。
4. **备份参数写坏后的恢复上限。** 现有恢复路径依赖相机仍能连上服务模式。如果某个值导致相机无法正常启动，服务模式还能不能进，未经验证。
